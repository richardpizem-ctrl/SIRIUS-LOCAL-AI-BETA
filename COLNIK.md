# COLNÍK 6.x — IPC Manager Module  
**Status:** Completed  
**Version:** 6.x  
**Component:** COLNIK  
**Role:** Central IPC manager between AUTONOMY → EXECUTE → AUTONOMY

---

## 1. Purpose  
The COLNÍK 6.x module is the central IPC (Inter‑Process Communication) layer of the SIRIUS Local AI system.  
Its primary responsibility is to safely, consistently, and deterministically transfer proposals generated by the Autonomy Engine to the Execute layer, collect responses, and maintain a stable operational cycle.

COLNÍK ensures that autonomous decisions are processed without risking system integrity.

---

## 2. Architecture Overview  
AUTONOMY → proposals.json → COLNIK → EXECUTE → responses.json → AUTONOMY


**Key IPC files:**
- `IPC_DATA/proposals.json` — incoming proposals  
- `IPC_DATA/responses.json` — execution results  
- `EXECUTE/executor.py` — execution engine  

---

## 3. Operational Cycle  

### Step 1 — Load Proposals  
COLNÍK reads `proposals.json`.  
If the file does not exist, the module enters an idle state and waits for the next autonomy cycle.

### Step 2 — Validate  
- Integrity checks  
- Duplicate detection  
- Critical‑file protection  
- Confirmation requirements for sensitive operations  

### Step 3 — Execute  
COLNÍK launches the execution module:

EXECUTE/executor.py


The executor processes all proposals and generates structured responses.

### Step 4 — Store Responses  
Execution results are written to:

IPC_DATA/responses.json


### Step 5 — Cleanup  
After successful processing, COLNÍK removes:

IPC_DATA/proposals.json


This prevents re‑processing and ensures a clean IPC state.

### Step 6 — Idle Mode  
COLNÍK waits for the next autonomy cycle.

---

## 4. Safety Rules  

### Critical Safety Guarantees  
- **No automatic deletion of critical files**  
- **Duplicate files are always REPORT_ONLY**  
- **System‑level changes require explicit confirmation**  
- **No dependency on Devin parser or any NLP subsystem**  
- **COLNÍK never modifies autonomy logic**  

These rules ensure that autonomous behavior cannot damage the system.
