# 🚀 6. Version 5.9.1 – Dual-Language KG Architecture, Lossless Entity Merge & Comprehensive System Security Protocol (Current Milestone)

Version 5.9.1 introduces a major architectural leap, solving language collision issues, enabling native in-memory entity consolidation, establishing automated taxonomical inference, and delivering a multi-layered local security architecture[cite: 1, 2].

Delivered:

### 🌐 Dual-Language Isolated KG Architecture (`autosave_kg.json` & `autosave_kg_en.json`)
- strict physical and logical partition between Slovak (`autosave_kg.json`) and English (`autosave_kg_en.json`) graphs, eliminating bilingual query contamination and mixed summaries[cite: 1, 2]
- dynamic language context switching: `RuntimeCore` automatically binds queries, node retrieval, attributes, and relations dynamically based on the active UI language flag (`SK` / `EN`)[cite: 1, 2]
- independent atomic dual autosaves on runtime shutdown or post-enrichment[cite: 1, 2]

### 🔀 Native Lossless KG Merge Engine (`kg merge <src> into <tgt>`)
- integrated directly inside `RuntimeCore` without external scripts or brittle import pathways[cite: 1, 2]
- zero-loss attribute relocation: migrates all properties, descriptions, alternative summaries, and habitat data from source to target[cite: 1, 2]
- automatic alias transition: source entities are preserved as lightweight alias nodes (`src -[alias]-> tgt`), enabling seamless bi-directional discovery[cite: 1, 2]

### 🧬 Taxonomical & Marsupial Inference (`KG_VERIFY`)
- context-aware biological deduction: automatically recognizes that marsupials and macropods belong to mammals without requiring rigid Wikipedia exact matches[cite: 1, 2]
- persistent edge auto-commit: once verified via Envoy or inference, relations (`kangaroo -[is_a]-> mammal`, `macropus -[je]-> cicavec`) are committed directly to disk with zero confirmation recurrence[cite: 1, 2]

### 🌍 Non-Destructive Reverse Location Engine (`_execute_reverse_location_query`)
- universal multi-stem matching supporting inflected geographical terms across both languages (*Austrálii*, *Austrália*, *Australia*)[cite: 1, 2]
- false-positive flora guard: eliminated naive substring collisions that previously misclassified tree-dwelling animals (*„stromový vačkovec“*) as flora[cite: 1, 2]
- direct attribute access: standardized traversal via `self.kg.get_attributes()`, preventing silent lookup failures[cite: 1, 2]

### 🔤 Punctuation Hygiene & Confirmation State Latching
- greedy trailing punctuation stripping (`.rstrip("?")`): prevents entity lookup mismatch (e.g., `CO JE MACROPUS?` cleanly resolves to node `macropus`)[cite: 1, 2]
- confirmation state latching: workflow fallback prompts strictly maintain pending entity identifiers in memory, ensuring affirmative user confirmations (`ÁNO`, `YES`) trigger Envoy execution reliably[cite: 1, 2]

### 🛡️ Comprehensive Security Protocol (COLNÍK Guard & HitL Safe Trash)
- Safe UI Trash (Human-in-the-Loop): files flagged for removal (duplicates, empty folders, damaged files) are quarantined; direct unverified file destruction is blocked, requiring explicit approval via `GET /trash`[cite: 2]
- COLNÍK Guard Shell Access Control: 0.0s hard blocking of forbidden commands (`format`, `rmdir /s`, `del /f /s /q c:`, `diskpart`, `drop database`), prompt checks for risky commands, and safe execution for telemetry (`mem`, `ps`, `sys`)[cite: 2]
- Token Guard: entry-level sanitization rejecting corrupted or dangerous symbol sequences (`@#$%^&*`) on raw input before runtime processing[cite: 2]
- Automatic Sliding-Window Quarantine Rotation: enforces a strict 100-file ceiling inside `COLNIK-6.x/envoy/quarantine/`, automatically pruning older JSON payloads upon new arrivals[cite: 2]
- Character Encoding Stabilization: multi-stage shell output decoding (UTF-8 -> CP1250 -> CP852 fallback) ensuring full diacritics integrity[cite: 2]

# 🛡️ Hybrid Isolation Layer (HIL) – Future Security Architecture (v7.x)

Modern operating systems rely primarily on sandboxing to isolate untrusted software:

- Chrome Sandbox
- Android Sandbox
- Windows Defender Sandbox
- Docker Containers

However:

### ❌ A technical sandbox is NOT the same as an OS logical quarantine.

A sandbox isolates a *process*.  
SIRIUS Quarantine isolates *logic*.

SIRIUS introduces an architectural paradigm that protects the host from internal logical failure:

### **SIRIUS Quarantine isolates:**
- malformed modules and configuration drifts
- inconsistent Knowledge Graph mutations[cite: 1]
- unverified autonomy proposals[cite: 1]
- broken workflow steps
- conflicting reasoning deductions
- duplicate, conflicting, or corrupted file states[cite: 2]
- invalid semantic transitions

### **Sandbox = Technical Isolation**  
Protects the OS *from applications*.

### **Quarantine = Logical Isolation**  
Protects the OS *from its own faulty logic*.
