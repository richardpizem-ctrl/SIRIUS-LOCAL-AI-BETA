# PROFESSOR SUBSYSTEM GOVERNANCE & EXECUTION PROTOCOL (V2.0)
**Security Classification:** STRICT AIR-LOCK INTERFACE  
**Operational Objective:** Deterministic Knowledge Graph saturation and bilingual synchronization across isolated SK/EN environments.

---

### ARTICLE I: INITIATION & SCHEDULING CONSTRAINTS
1. The execution routine integrated directly within `sirius_orchestrator.py` and supporting runtime modules MUST NOT execute batch saturation unless all of the following preconditions evaluate to `TRUE`:
   - The file locks (`kg_lock.lock`) for respective storage modules are released and writable.
   - The primary orchestrator reports a continuous idle duration exceeding configured thresholds.
   - The total validated node/edge metric in target JSON repositories remains below saturation limits.

---

### ARTICLE II: NETWORK GATEKEEPER & INGESTION RULES
1. **Domain Whitelist Enforcement:** Network connections are restricted strictly to fully qualified domain names listed in configuration sources. HTTP redirects pointing to unlisted hosts must be severed immediately.
2. **Payload Sanitization Pipeline:**
   - Ingested payloads must pass through an HTML/XML tag stripper and token guard filter prior to memory ingestion.
   - Any continuous string exceeding character length limits without valid grammatical punctuation marks must be dropped.
   - Strings containing command injection signatures (`IGNORE PREVIOUS`, `SYSTEM:`, `DELETE_NODE`, `<SCRIPT>`) must trigger immediate rejection and endpoint demotion.

---

### ARTICLE III: LINGUISTIC & EPISTEMIC VALIDATION PIPELINE (GRAMMARENGINE 2.0)
1. **Bilingual Knowledge Isolation:** Graph storage and relational ingestion are strictly separated into parallel localized repositories (`autosave_kg.json` for Slovak, `autosave_kg_en.json` for English) to prevent cross-language contamination.
2. **Advanced Dependency Extraction:** Candidate triplets are admitted to staging quarantine if the syntactic tree resolves unambiguously across supported patterns:
   - Slovak: `[Subject] -> [Reflexive/Active Predicate containing sa/si] -> [Object with preserved conjunctions a, i]`
   - English: `[Subject] -> [Transitive / Phrasal Verb (e.g., deals with, focuses on)] -> [Object with filtered articles]`
3. **Sliding-Window Quarantine & Rotation:** New triplets must endure retention windows or obtain multi-domain corroboration before eligibility for promotion. Automatic sliding window quarantine file rotation prevents log bloating.

---

### ARTICLE IV: ATOMIC COMMIT & DATA INTEGRITY PROTOCOL
1. **Pre-Commit Sequence:**
   - Acquire exclusive system file handle lock on the target knowledge graph storage.
   - Read and store baseline version from the active database (`autosave_kg.json` or `autosave_kg_en.json`).
   - Write merged graph into transient disk location (`.tmp`).
   - Run complete JSON schema validation and AST syntax integrity checks.
2. **Execution & Promotion:**
   - Perform atomic filesystem operation (`os.replace`) upon version verification.
   - Increment persistent version counters.
   - **SafeRollback Integration:** In case of collision, syntax failure, or structural corruption, the built-in `SafeRollback` module (`safe_rollback.py`) bypasses Git dependencies, executing granular module-level backups (`shutil.copytree`) and instant restorations (`shutil.rmtree`) to restore the last known healthy state.

---

### ARTICLE V: PROFESSOR GOVERNANCE & UI FEEDBACK GATEWAY
1. **Professor Validator Matrix:** Every raw output generated by the underlying runtime must pass through the Professor Validator middleware before reaching the UI panel (V2), resolving into one of three deterministic states:
   - **PASS:** High factual consistency and completeness; released immediately to the UI with dynamic language error handling.
   - **WARN:** Usable data with low confidence markers; dispatched with visual uncertainty indicators.
   - **REJECT:** Incomplete, corrupted, or contradictory data (`INCOMPLETE_FACTS`, `LOW_CONFIDENCE`, `CONTRADICTION`). The response is blocked, returning a structured rejection JSON object.
2. **Autonomous Offline Execution:** SIRIUS operates as an autonomous cognitive orchestrator running locally via IPC bridge on port 8080, combining zero-code learning, direct declarative sentence parsing, and deterministic runtime stability.
